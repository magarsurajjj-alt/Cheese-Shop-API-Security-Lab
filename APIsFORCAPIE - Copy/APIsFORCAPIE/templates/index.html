Vulnerable API - OWASP Top 10 Vulnerabilities

Introduction

Welcome to the OWASP Top 10 Vulnerabilities demonstration. This tutorial will guide you through exploiting common vulnerabilities in a real-world API. Please ensure that you follow each step and understand the risks and countermeasures for each vulnerability.

Important: This environment is intended for educational purposes only. Do not use these techniques against unauthorized systems.

1. Broken Authentication

Broken Authentication is one of the most common vulnerabilities. It occurs when an attacker can easily bypass authentication mechanisms to gain unauthorized access.

Steps to Exploit:

  1. Send a POST request to the /register endpoint with the following payload:
    2. { "username": "admin", "password": "password123" }
  2. If successful, register a new user with weak credentials (e.g., "admin:password123").
  3. Attempt to log in using weak authentication. You should not have proper rate limiting or account locking on the endpoint.
  4. Use brute-force tools like Burp Suite Intruder to attempt various username/password combinations.

2. Excessive Data Exposure

Excessive data exposure occurs when an API endpoint reveals too much information, which could lead to data leakage.

Steps to Exploit:

  1. Send a GET request to the /user/{id} endpoint using any valid user ID (e.g., 1 or 2).
  2. Inspect the response. It should return the user's username, but it also includes the password field, which is sensitive.
  3. Ensure that sensitive fields like password and other PII (Personally Identifiable Information) are returned in the response.

3. Lack of Resources & Rate Limiting

In this scenario, an API may not limit the amount of data it returns, leading to performance issues or abuse.

Steps to Exploit:

  1. Send a GET request to the /data endpoint.
  2. The API should return a large number of items. This can overwhelm the server or client if there are no rate limits in place.
  3. Repeat the request several times in a loop to test for denial-of-service conditions.

4. Broken Function Level Authorization

Broken Function Level Authorization occurs when users can access resources they are not authorized to access, such as admin-only data.

Steps to Exploit:

  1. Send a GET request to the /admin endpoint without any authentication or authorization.
  2. Since there are no checks in place, you should be able to access the admin data even though you are not an admin.

5. SQL Injection (SQLi)

SQL Injection occurs when an attacker is able to manipulate an API's SQL query by injecting malicious input into the request.

Steps to Exploit:

  1. Send a GET request to the /user/{id}/sqli endpoint, with a malicious SQL injection payload.
    2. /user/1/sqli?param=' OR '1'='1
  2. The API should return unexpected results or allow unauthorized access to the data.
  3. Try different SQL injection payloads to see how the application reacts.

6. Cross-Site Scripting (XSS)

Cross-Site Scripting (XSS) occurs when an attacker injects malicious JavaScript code into a page viewed by other users.

Steps to Exploit:

  1. Send a POST request to the /comment endpoint with a malicious JavaScript payload in the comment content.
    2. { "content": "" }
  2. The script should execute in the browser of any user viewing the comment, triggering an alert box.

7. Insecure Deserialization

Insecure Deserialization occurs when untrusted data is deserialized without proper validation, leading to code execution or other vulnerabilities.

Steps to Exploit:

  1. Send a POST request to the /deserialize endpoint with a malicious payload designed to exploit insecure deserialization.
    2. { "data": "malicious_payload" }
  2. Observe if the API attempts to deserialize the data without proper checks, leading to a potential code execution or denial-of-service.

8. Using Components with Known Vulnerabilities

Using components with known vulnerabilities refers to relying on outdated or insecure libraries or services in your application.

Steps to Exploit:

  1. Identify the libraries and services being used by the API.
  2. Check for known vulnerabilities in these components using databases like CVE (Common Vulnerabilities and Exposures).
  3. Attempt to exploit known vulnerabilities by using publicly available exploit tools or techniques.

9. Insufficient Logging & Monitoring

Insufficient logging and monitoring make it harder to detect attacks and react quickly when a vulnerability is exploited.

Steps to Exploit:

  1. Perform various attacks on the API, such as SQLi, XSS, and others.
  2. Check the logs for signs that the attacks are being detected and logged.
  3. If no logs are generated or alerts triggered, this indicates insufficient logging and monitoring.

10. Server-Side Request Forgery (SSRF)

Server-Side Request Forgery (SSRF) occurs when an attacker can send requests from the server to internal or external resources, bypassing firewall rules.

Steps to Exploit:

  1. Send a request to an endpoint that accepts an external URL and allows it to be used internally, such as a URL fetcher.
    2. /fetch_url?url=http://localhost:8000/admin
  2. Bypass firewall rules and access internal services that would otherwise be protected.
